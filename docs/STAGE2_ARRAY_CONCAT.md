# Stage2 array.concat return identity

`array_concat` and `array_concat_v1` append the source's detached values into the target and return the exact target `ReferenceHandle` after mutation succeeds. This also applies to a target slice: its returned ID remains the slice ID and its existing parent link controls insertion. No array allocation is added. A detached copy remains independent. Self-concat reads the source before mutation, duplicating its original elements once.

The contract follows the official [v4](https://www.tradingview.com/pine-script-docs/v4/essential/arrays/#concatenation), [v5](https://www.tradingview.com/pine-script-docs/v5/language/arrays/#concatenation) and [v6](https://www.tradingview.com/pine-script-docs/language/arrays/#concatenation) first-ID return and alias examples. The source remains unchanged when distinct and unaliased; self or linked-view sources naturally observe the target mutation. Self-concat and slice compositions are derived expectations, not TradingView-exported observations.

The ABI retains its `id1` and `id2` parameters. The existing `METHOD_RECEIVER` injection binds only the `id1` parameter of the `array.concat` method. Its catalog return changes from `void` to `array<T>`, which the existing manifest owner classifies as `REFERENCE`. The two concat manifest rows change; all other manifest fields remain identical. Callable availability stays namespace v4/v5/v6 and method v5/v6: five canonical versioned tuples, four within v5/v6. There is no new compiler capability, reference schema, checkpoint revision or lifecycle owner.

The independently authored fixture contains 30 cases across v4/v5/v6, including float/int/bool/string values, empties, self-concat and mutation through the result. Its exact SHA256 is `20d833ca9c31265c48c250dbec7edc5a9da3f9b2885e098fd0196e4d4e86ee9e`. Tests exercise both the native collection owner and public ABI; generated compiler execution is a separate integration path, not a second runtime mode.

The 112 new owner tests add source/target/self/overlapping slice and copy controls; ordinary and varip realtime abort, same-sequence retry and final commit; full/compact JSON checkpoint restoration; existing invalid-kind/missing-ID guards; and resource overflow without partial parent/slice mutation. They also pin unchanged non-concat manifest content and availability. The initial valid baseline had 92 failures and 20 passes. Both Python 3.11 and 3.13 pass all 112 after the change. No existing tests or expected results were changed.

The array mutation and validation algorithms are unchanged. This work does not define new behavior for missing array IDs, mixed element types, arbitrary host values or general collection coercion. Producer typed specialization and named argument admission remain their existing owner's responsibility. Stage2 acceptance requires the coordinated integration and Linux checks; these tests establish this bounded return/alias contract only.
