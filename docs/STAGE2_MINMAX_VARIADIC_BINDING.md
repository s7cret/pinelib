# Stage2 min/max repeated-source binding

The existing numeric ABI already accepts positional `*values` for `min_v1` and `max_v1`. Its implementation, error handling and numeric/NA policies are unchanged. The target manifest previously described the source group as one scalar binding, so the compiler lacked an explicit contract for forwarding every source argument. This change adds `variadic: true` to that group's source metadata and uses `SOURCE_VARIADIC` for its ABI binding.

The owner grants that binding only when the official row is a function named `math.min` or `math.max`, the matching source group is `values` with the exact boolean `variadic=True`, and the ABI parameter has kind `VAR_POSITIONAL`. Missing/false/numeric flags, keyword or fixed ABI parameters, methods and other names remain outside that profile. `values` is the existing canonical source group; this change does not assert new Pine named-argument spellings or define a new source arity rule. The producer owns variadic source admission and the compiler owns checked argument expansion.

Only two official target rows change: their `parameters` and `parameter_bindings`, plus the outer content hash. The canonical tuple denominator is four, `math.min`/`math.max` in Pine v5/v6. Their availability, overload IDs, return contracts, numeric capability and pure evaluation model stay unchanged. No historical call binding is added. Existing v1-v4 native catalog aliases continue to reference the same versionless ABI functions; this does not claim those aliases have acquired modern source bindings.

The shared manifest schema revision and capability set are unchanged. `SOURCE_VARIADIC` is an explicit new binding kind that requires the coordinated consumer update. An older compiler must reject an unknown binding kind; no name guessing or scalar fallback is authorized. Generated modules retain their exact target-manifest hash check.

The new tests check both modern rows and all six version admission boundaries, exact receiver/argument shape guards, unchanged historical catalog identities and signatures, complete finite argument lists, canonical NA at different positions, and existing rejection of empty input, keywords, bool/string/null/nonfinite values. These ABI checks preserve existing behavior; they are not new claims about Pine coercion for unsupported source values. The before-baseline run contains 14 failures and 55 passes. A separate guard-before run preserves the initially over-broad marker cases and stale materialized manifest.

The baseline is the immutable search commit `ff3fda01541795c793068bced47a0d195bf27e37` plus the frozen concat bundle `6b53f0ff67c05081e7eda1efc1c46b05806508d9461a807c5ddf3b3ef6d8dcc1`. The original concat bundle and all existing test bytes are preserved. Its earlier test of an unchanged entire non-concat manifest is expected to conflict with this authorized min/max change; that old expectation must receive an explicit separate review before a combined gate is accepted. It is not skipped or altered in this owner delta.

The target file is regenerated and checked with the normal `python -m pinelib.abi build` CLI. Local validation and raw/LF source receipts describe the isolated directory only; no live checkout, published source, checkpoint owner or array behavior is changed by this work. Full Stage2 acceptance remains pending.
